# 论文笔记写作规范

本规范适用于 `notes/` 下的速读卡、精读和模板，是仓库根目录 [AGENTS.md](../AGENTS.md) 的补充。笔记应阐明研究动机、设计依据及实验结论的支持范围。

## 文献范围

- 笔记只依据论文正文及其附录，明确所据版本。与已有工作的比较应有相应论文依据。
- 不开展源码分析、代码复现或运行实验，不用官方代码补全论文未披露的机制、参数或实验设置。登记中的代码发布状态与链接不展开为笔记正文。
- 论文中的伪代码、算法步骤、公式和实验设计属于解读范围；可以解释其含义，但不补造实现。
- 材料未纳入分析时说明证据范围，不将“未读到”写成“论文未披露”。作者主张、论文证据与解读者推断分别表述。

## 论证主线

按“**已有困难 → 关键观察 → 方法设计 → 实验证据 → 研究结论**”组织内容。

1. **已有困难**：明确任务、目标与必要的输入输出，说明相关方法及其局限。
2. **关键观察**：解释作者据以提出核心思路的观察或判断，说明设计依据及其与研究困难的对应关系。论文未单列时可据原文归纳，并明确是归纳，不替作者补造动机。
3. **方法设计**：先给整体框架，再展开关键机制。每项设计对应前面的困难或观察，明确对象、作用与衔接关系；公式随解释引入，定义必要符号并保留原文编号。
4. **实验证据**：每组实验回答一个明确问题，依次说明验证目的、必要设置、结果与支持范围。区分整体效果、组件贡献和相关性观察，不将缺少识别依据的结果写成因果结论。
5. **研究结论**：收束论文支持的认识、贡献、适用条件与主要局限，提炼可参考的思想。未披露细节只保留影响核心结论理解的内容，不穷举实现参数。

开头可以简短概括全文，正文沿论证主线展开。章节名称与数量可按方法、基准或审计论文调整，不能为套模板补造训练流程或损失函数。

“关键观察”也可表现为核心假设或设计思路，按论文实际论证命名。组件贡献的归因需要适当的对照设计，消融结果也须结合控制条件解释。精读的可参考点只在有明确迁移启示时展开，否则省略；速读卡不设置该字段。

## 行文风格

- 采用客观、严谨的技术文体。论证顺序参考学术汇报，成文使用准确的书面表达；通过定义、因果关系与必要示例提高可读性。
- 标题直接概括研究对象、机制或实验目的，避免口语化设问、对话措辞、拟人化表达和宣传性判断。
- 正文明确陈述对象、条件、机制与结果，减少“先看……就能理解”等面向读者的指令。不以口语类比代替机制解释，也不以生僻词或抽象名词堆叠制造学术感。

## 速读与精读的分工

- **速读卡**：按 [_template_card.md](_template_card.md) 压缩呈现论证链，帮助读者理解贡献并决定是否精读。只选关键机制与证据，不摘录全部公式、模块、超参或实验表格。
- **精读**：按 [_template_deep.md](_template_deep.md) 连贯解释完整论证链。先建立直觉和框架，再展开细节；案例放在它所解释的机制附近。模块分工、执行顺序、反馈与跨轮迭代关系分别说明。
- P1–P10 用于辅助检索与横向比较，不主导讲解顺序；问题映射保持简短，不重复展开机制、实验和局限。
- 速读卡先列“主要”问题，再列“涉及”问题；基线或背景工作写“无（作为基线或背景工作收录）。”。相邻方法区分已收录工作直接借用、机制相似与分析者提出的迁移，未见直接借用时如实说明。
- 同一内容在最合适的位置解释，其他位置按需引用，不在开头、问题表、局限与结尾反复复述。实质影响机制理解的条件就近交代，其余局限集中说明。

## 证据与表达

- 本目录使用“论文明确、公式推出、未披露”标明依据，解读者的推断另作说明；不将作者声明直接视为已独立验证的事实。
- 关键结论就近注明章节、公式、算法或表格来源。作者的创新主张与实验支持分开，不在缺少依据时声称首创或全面优越。
- 结果保留影响解读的市场、时间切分、评价单位、指标、预算与成本口径；不同口径分别说明，不把数值并列当作公平比较。
- 示意例子明确标为示意，不写成论文实例或实验结果。术语首次出现时解释，符号仅在需要时引入。
- 维护过程只写入本地 `WORKLOG.md`，不写进笔记。笔记中不包含阅读、检索、补写、核查、工具执行或访问报错记录。

## 格式与维护

- 速读卡保留“主要工作/创新点、针对问题与证据、局限”三个字段及问题行语法，遵守根目录的问题标注规则；生成的元数据不手改。
- 精读保留含“核心结论、针对的问题、实验、未披露”的章节标题，以兼容现有校验；这些关键词不决定正文的讲解重心。
- 新增工作独立维护登记与笔记，索引由脚本生成，不要求联动改写旧笔记或专题。既有笔记按任务范围调整，不因模板更新自动批量重写。
